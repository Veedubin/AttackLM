## Phase 1: Critical Fixes (P0) — Must Fix Before Anything Else

**Rationale**: These are dead-code and broken-path bugs that block functionality. Fix them first so Phase 2+ features build on a solid foundation.

### 1.1 Fix PiSSA Init Dead Code
- **Severity**: P0 — flag parsed but never passed to LoraConfig
- **Root cause**: `train_all.py::build_train_cmd()` never forwards `--pissa-init` to `train_template.py`. `train_template.py` handles it correctly (line 1981-1982: `if args.pissa_init: init_lora_weights = "pissa"`), but the flag never arrives when training via `attacklm train --all`.
- **Fix**:
  1. Add `--pissa-init` argparse argument to `train_all.py` parser (near line 720, alongside `--loftq-init`)
  2. Add passthrough in `build_train_cmd()` (near line 414, alongside `loftq_init`): `if getattr(args, "pissa_init", False): cmd.append("--pissa-init")`
- **Files**: `scripts/train_all.py` (2 locations)
- **Agent**: `re-coder`
- **Effort**: 15 min
- **Dependencies**: None
- **Parallel**: ✅ Can run in parallel with 1.2

### 1.2 Wire auto_tune_vram() Call Site
- **Severity**: P0 — 115 lines of dead code, function defined but never called
- **Root cause**: `auto_tune_vram()` (line 1705 in `train_template.py`) is a complete implementation that finds optimal `max_length` for the GPU/model combination, but no code path ever invokes it. The `--auto-tune` flag is parsed (line 249) but the function is never called.
- **Fix**: Add a call site in the training flow, after model load but before training starts. The function takes `(args, model_loading_fn)` and returns a dict with `optimal max_length`, `batch_size`, and `tok/s`. Apply the returned values to override `args.max_length` and `args.batch_size` before SFTConfig creation.
- **Files**: `scripts/train_template.py` (1 new call site, ~10 lines)
- **Agent**: `re-coder`
- **Effort**: 30 min
- **Dependencies**: None
- **Parallel**: ✅ Can run in parallel with 1.1

## Phase 5: Memory Optimization — New Training Methods

**Rationale**: These features reduce VRAM requirements and improve training efficiency. However, they ALL touch `train_template.py` — this is a serial bottleneck. Order matters because later items may depend on earlier refactoring.

### 5.1 COAP Optimizer (Replaces GaLore)
- **Impact**: HIGH — 81% optimizer memory reduction with 8-bit, 4x faster than GaLore
- **Fix**: Add `--use-coap` flag. COAP (Coupled Optimization with Adaptive Projection) replaces GaLore's SVD-based projection with a more efficient scheme. Integrate as a new optimizer path alongside existing GaLore/Q-GaLore.
- **Files**: `scripts/train_template.py` (new optimizer path, ~50 lines)
- **Agent**: `re-coder`
- **Effort**: 1.5 hours
- **Dependencies**: None (but must be first in Phase 5 since it touches the optimizer selection logic)
- **Parallel**: ❌ (serial — same file as all Phase 5 items)

### 5.2 FlashOptim (Replaces LOMO)
- **Impact**: HIGH — 50% memory reduction vs LOMO
- **Fix**: Add `--use-flashoptim` flag. FlashOptim improves on LOMO by using fused backward passes. Integrate as alternative to `--use-lomo`.
- **Files**: `scripts/train_template.py` (new optimizer path, ~30 lines)
- **Agent**: `re-coder`
- **Effort**: 1 hour
- **Dependencies**: After 5.1 (optimizer selection logic refactored)
- **Parallel**: ❌

### 5.3 Unsloth Gradient Checkpointing "unsloth" Mode
- **Impact**: HIGH — 30% VRAM savings, one-line change
- **Fix**: When `--use-unsloth` is active, set `gradient_checkpointing="unsloth"` instead of `gradient_checkpointing=True`. This is literally a one-line change in the TrainingArguments/SFTConfig.
- **Files**: `scripts/train_template.py` (1 line change in SFTConfig)
- **Agent**: `re-coder`
- **Effort**: 10 min
- **Dependencies**: After 5.1 (SFTConfig creation may be refactored)
- **Parallel**: ❌

### 5.4 Mixed-Precision LoRA (2+4 bit Layer-Wise)
- **Impact**: HIGH — 35-45% VRAM savings
- **Fix**: Add `--mixed-precision-lora` flag. Implements layer-wise mixed precision: attention layers at 4-bit, MLP layers at 2-bit. Requires custom quantization config.
- **Files**: `scripts/train_template.py` (custom quantization config, ~40 lines)
- **Agent**: `re-coder`
- **Effort**: 1 hour
- **Dependencies**: After 5.3 (quantization config logic)
- **Parallel**: ❌

### 5.5 FP8 Training (Hardware-Gated)
- **Impact**: HIGH if hardware supports it (H100/Blackwell), MEDIUM otherwise
- **Fix**: Add `--fp8` flag with hardware detection. If GPU supports FP8 (sm_90+), enable FP8 mixed-precision training via `torch.amp`. If not, print clear error with hardware requirements.
- **Files**: `scripts/train_template.py` (FP8 amp setup, ~30 lines)
- **Agent**: `re-coder`
- **Effort**: 45 min
- **Dependencies**: After 5.4
- **Parallel**: ❌

### 5.6 BitNet+LoRA Support
- **Impact**: HIGH — 60-75% VRAM savings, but needs natively trained BitNet models
- **Fix**: Add `--use-bitnet` flag. When active, load model in BitNet format (1.58-bit ternary weights) and apply LoRA on top. Requires BitNet-compatible base model.
- **Files**: `scripts/train_template.py` (BitNet loading path, ~50 lines)
- **Agent**: `re-coder`
- **Effort**: 1.5 hours
- **Dependencies**: After 5.5
- **Parallel**: ❌

### 5.7 SignRoundV2 Quantization
- **Impact**: HIGH — QAT-level accuracy at PTQ cost
- **Fix**: Integrate SignRoundV2 into `convert_to_gguf.py` as an alternative quantization method. Add `--quant-method signround` flag.
- **Files**: `scripts/convert_to_gguf.py` (new quantization path, ~40 lines)
- **Agent**: `re-coder`
- **Effort**: 1 hour
- **Dependencies**: None (different file from train_template.py!)
